# 実装計画

## 原則

publicリポジトリを前提に秘密・実データを残さず、変更操作は読み取りから段階的に分離します。各段階で対象Redmineのバージョン、独自改修、API、権限、カスタム項目を実機検証し、その結果が承認されるまで次段階を本番利用しません。APIキーの権限はツールでは制限できません。

## PR-1: 基盤・読み取り専用出力

- Python CLI、厳格なURL/TOML検証、環境変数または非表示入力によるキー取得
- GET限定クライアント、認証check、プロジェクト必須のexport
- 全ステータス、既定の子プロジェクト除外、任意トラッカー、固定ソート
- 防御的ページングと上限、選択項目だけのUTF-8 BOM付きCSVとUTF-8 JSON、実行単位の一意なrunディレクトリ公開
- HTTPをモックした異常系・機密非表示・出力テスト、Windows/CA/proxy/実機確認文書

受入条件は、全自動テスト通過、GET以外が存在しないこと、未完取得が出力されないこと、チェックリストの確認結果が「未実施」と明記されることです。

## PR-1.1: 実機確認結果と読み取り専用UX

- Windows 11での初回導入、PC再起動/新規PowerShell後の再開、実機照合runbook
- 固定GET endpointによるproject identifier/数値IDの安全なresolution
- APIの `created_on` / `updated_on` raw値を保持した、明示opt-inのJST表示列
- basic schemaを維持しながら標準追加項目、本文、custom field、個別issue情報を許可リストで段階導入する設計

許可するHTTP操作は `GET /users/current.json`、`GET /issues.json`、
`GET /projects/{id_or_identifier}.json` だけです。変更候補生成、変更系API、個別issue endpointは
追加せず、PR-2の計画も変更しません。

## PR-1.2: extended standard fields（今回）

- 既定のbasicを完全に維持し、明示 `--fields extended` だけで標準10項目を固定許可リスト出力
- 欠損/null/非null値をJSONと値なしmetadata集計で区別し、型・範囲・長さを安全に検証
- 既存JST opt-inとの直交した組合せ、固定CSV列、HTTPをモックした互換・異常系テスト
- QUICK2での返却shape、権限差、GUIとの業務的対応は未確認で、マージ後に承認済み少数件で確認

許可GET endpointと検索条件を増やさず、本文、custom field、個別issue情報、変更候補は対象外とする。

## PR-2: 変更候補の作成（計画のみ）

実環境で確認した業務条件を設定可能なルールとして追加し、読み取り結果から変更候補のローカルレビュー資料だけを生成します。dry-run、候補理由、入力スナップショット識別、二者レビュー、再取得時の差分検証を設計します。この段階でもRedmineを変更しません。

## PR-3: ウォッチャー追加（計画のみ）

対象環境のwatcher API、必要権限、ユーザー識別子、重複時挙動、監査要件を検証後、PR-2候補を明示承認して限定的に追加する専用コマンドを設計します。任意パス/メソッドは提供せず、件数上限、dry-run既定、再認証、操作記録（秘密・本文なし）、部分失敗時の再開方針を必須にします。

## PR-4: ステータス変更（計画のみ）

ワークフロー、ロール、必須項目、ロック/同時更新、許可遷移、コメント要否を実機検証します。チケットIDと期待する更新時刻を含む承認済み候補だけを対象にし、実行直前再取得、競合停止、小バッチ、明示確認、監査記録、ロールバック不能時の手順を設計します。作成・削除や汎用API操作は対象外のままです。

## 各PRのゲート

1. テスト環境で最小権限の専用アカウントを使用する。
2. API/画面の件数・値、子プロジェクト、カスタム項目、権限を照合する。
3. セキュリティ、業務所有者、運用担当の承認を得る。
4. 本番は承認済み保存先・CA・proxyを使い、少数件から開始する。
5. 実測結果と未確認事項を記録し、架空の合格記録を作らない。
